# QGram для iOS

Нативное iOS-приложение для [qgram.fun](https://qgram.fun) на SwiftUI. Работает
поверх публичного JSON API (`API_USAGE.txt` в корне репозитория), без вебвью.

- **Язык / UI:** Swift 5, SwiftUI, минимум **iOS 16.0**, iPhone + iPad.
- **Bundle ID:** `fun.qgram.ios`, версия `1.0 (1)`.
- **Архитектура:** MVVM. Экраны — `View` + `@MainActor` ViewModel, сеть — один
  `actor APIClient`, состояние сессии — `AppState` (`@EnvironmentObject`).
- **Дизайн:** перенесён из веб-версии (`static/style.css`, «QGram Design System
  v2»): фон `#0F0F0F`, карточки `#1A1A1A`, бренд `#9F5AFD → #C084FC`, радиусы
  12/16/20. Есть светлая тема и переключатель в настройках.

## Как открыть и собрать

```bash
open ios/QGram.xcodeproj
```

Дальше в Xcode (15 или новее): выбрать схему **QGram**, подставить свою команду
разработчика в *Signing & Capabilities* (проект идёт без `DEVELOPMENT_TEAM`), и
запустить на симуляторе или устройстве. Архив для App Store — *Product → Archive*.

Проектный файл сгенерирован скриптом. После добавления/удаления файлов:

```bash
python3 ios/scripts/generate_xcodeproj.py
```

## Особенности API, учтённые в клиенте

Это не косметика — без этих деталей приложение вело бы себя неправильно:

1. **Время приходит в наивном UTC** (`2026-08-07T21:53:00`, без `Z`). Всё парсится
   форматтером с `TimeZone(UTC)` в `QDate`; иначе все даты смещались бы на часовой пояс.
2. **`GET /api/chats/<id>/messages?limit=N` без `before_id` отдаёт САМЫЕ СТАРЫЕ
   сообщения**, а не последние. Первая страница запрашивается с
   `before_id = 2147483647` (см. `AppConfig.latestMessagesSentinelID`).
3. **2FA-ответ приходит с HTTP 401** и `challenge_token` в теле, и каждый вызов
   `/api/login` шлёт новый код на почту — поэтому запрос делается ровно один раз,
   а тело читается напрямую.
4. **Сервер прячет часть API от мобильных браузеров** (`app_required`), но пускает
   клиентов с `Authorization: Bearer`. Заголовок ставится на каждый запрос, плюс
   собственный `User-Agent: QGramiOS/…`.
5. **Загрузка изображений проверяется по сигнатуре файла**, поэтому любое фото
   перекодируется в JPEG с расширением `.jpg` (HEIC из галереи сервер отклонил бы).
6. **Лимит баннера — 5 МБ** (в `API_USAGE.txt` указано 8 МБ, в `app.py`
   `BANNER_MAX_MB = 5`); клиент сжимает под 5.
7. **`/api/me` возвращает 403** для забаненного/замороженного аккаунта — приложение
   показывает отдельный экран блокировки, а не пустую ленту.
8. **Пагинация ленты по offset** может дублировать посты при новых публикациях —
   элементы дедуплицируются по `id`.

## Push-уведомления: что нужно доделать на сервере

Клиентская часть готова: приложение спрашивает разрешение, регистрирует APNs-токен
через `POST /api/push/devices` и снимает его при выходе. Чтобы пуши реально
доставлялись, на qgram.fun нужно:

1. Создать APNs-ключ (.p8) в Apple Developer и задать переменные окружения
   `APNS_KEY_P8`, `APNS_KEY_ID`, `APNS_TEAM_ID`, `APNS_TOPIC=fun.qgram.ios`
   (плюс `APNS_USE_SANDBOX=1` для сборок из Xcode).
2. Установить HTTP/2-клиент: `pip install 'httpx[http2]'` (APNs работает только
   по HTTP/2, в текущем venv его нет).
3. Включить Push Notifications у App ID; в проекте уже лежит
   `QGram/Resources/QGram.entitlements` с `aps-environment`.

Пока переменные не заданы, `/api/push/devices` возвращает `delivery_enabled: false`,
токены просто копятся, и ничего не ломается.

## Чего нет

- **Звонки** — вне объёма (нужен WebRTC-сигналинг поверх `/api/calls/*`).
- **Групповые чаты** — таблица `conversations` на сервере строго 1:1
  (`user1_id`/`user2_id` с UNIQUE), поэтому группы требуют переделки модели
  переписки на сайте, а не просто нового эндпоинта.

## Проверка перед сборкой

Swift-тулчейна на сервере разработки нет (Linux), поэтому компиляция и запуск
делаются в Xcode на macOS. Перед публикацией стоит прогнать:

1. `python3 ios/scripts/generate_xcodeproj.py` — проект пересобирается из файлов.
2. Сборка схемы QGram (⌘B) — предупреждений быть не должно.
3. Ручной проход: вход → лента → пост → создание поста → профиль → чат → выход.
